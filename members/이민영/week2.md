[OpenStack] 2. OpenStack 핵심 비교 컴포넌트 완벽 정리 (feat. 초보자를 위한 AWS 비교)

이전 글에서 OpenStack이 온프레미스 서버를 클라우드로 만들어주는 '클라우드 OS'라는 것을 배웠습니다.

그렇다면 OpenStack 내부에서는 과연 어떤 일꾼(=컴포넌트)들이 각자 무슨 일을 하고 있을까요?

OpenStack은 독립된 서비스들의 집합체입니다. 즉, 커다란 프로그램 통자 하나가 아니라 역할별로 나뉜 여러 부품이 각자의 DB와 API를 가지고 서로 협력하는 구조입니다. 초보자 관점에서 핵심 컴포넌트들을 하나씩 파헤쳐 보겠습니다.
<br>

#### 한눈에 보는 컴포넌트
| 컴포넌트 | 역할 | API 포트 | AWS 대응 서비스 |
| --- | --- | --- | --- |
| Keystone | 사용자 인증 및 출입증(토큰) 발급 | 5000 | IAM |
| Nova | VM 생성/삭제 주문 및 스케줄링 | 8774 | EC2
| Neutron | 가상 네트워크, IP, 라우터 생성 | 9696 | VPC 
| Glance | OS 부팅용 이미지(템플릿) 관리 | 9292 | AMI
| Cinder | 탈부착 가능한 가상 하드디스크(볼륨) | 8776 | EBS
| Placement | 전체 서버 자원 장부 (남은 CPU/RAM 계산) | 8778 | (내부 스케줄러)
| Horizon | 관리자용 웹 대시보드 (마우스 클릭 화면) | 80 / 443 | AWS Console
</br>

#### 핵심 컴포넌트 딥다이브
1. Keystone (Identity)
- AWS 대응 : IAM
- 무슨 일을 하나요 ?
    - 사용자 로그인 검증, 권한 관리, 프로젝트(테넌트)를 관리합니다.
    - "모든 API 요청의 첫 번째 문지기"입니다. Keystone에서 통과 인증(토큰)을 받지 못하면 아무것도 만들 수 없습니다.
> 토큰이 왜 필요한가?
로그인에 성공하면 Keystone이 임시 출입증(토큰)을 줍니다. 이후 Nova나 Neutron에 명령을 내릴 때마다 이 출입증을 보여줘야 요청이 거부당하지 않습니다.


> 테넌트 : 클라우드 자원을 빌려 쓰는 하나의 단위
AWS로 치면 계정(account)이나 조직 내 프로젝트에 해당함.

#### 2. Nova (Compute)
- AWS 대응 : EC2
- 무슨 일을 하나요?
    - VM(가상 머신)의 생성부터 스케줄링, 중지, 삭제까지 생명주기(Lifecycle) 전체를 관리합니다.
>     핵심 주의점 : Nova는 직접 VM을 만들지 않습니다!
Nova는 "몇 번 서버에 VM을 만들어라"라고 판단만 하고, 실제 VM을 띄우는 건 하위 하이퍼바이저(QEMU/KVM 등)에게 시킵니다. Nova는 '지시를 내리는 관리자'일 뿐입니다.

#### 3. Placement (Resource Tracker)
- AWS 대응 : AWS 내부 시스템 (비공개)
- 무슨 일을 하나요?
    - "1번 서버 : CPU 4개 남음", "2번 서버 : RAM 8GB 남음"처럼 각 물리 서버의 남은 자원을 실시간 장부에 기록합니다.
    - Nova가 VM을 새로 만들려고 할 때, Placement 장부를 확인하여 어디에 넣을지 결정합니다.

#### 4. Neutron (Networking)
- AWS 대응 : VPC
- 무슨 일을 하나요?
	
    - VM들이 서로 통신하고 외부 인터넷과 연결될 수 있도록 가상 선을 까는 역할입니다.
- Neutron이 만드는 핵심 네트워크 자원 5가지 :
  1. Network (L2) : 가상의 랜선/가상 스위치
  2. Subnet (L3) : 네트워크 안에서 사용할 IP 대역 (예 : 10.0.0.0/24)
  3. Router : 서로 다른 네트워크끼리, 혹은 외부 인터넷과 연결해 주는 가상 라우터
  4. Security Group (방화벽) : "22번 포트(SSH) 접속 허용"같은 인스턴스 보안 규칙.
  5. Floating IP (공인 IP) : 외부 인터넷에서 접속할 수 있도록 VM에 자유롭게 붙였다 뗐다 하는 유동 공인 IP

#### 5. Glance (Image)
- AWS 대응 : AMI (Amazon Machine Image)
- 무슨 일을 하나요?
  - VM을 만들 때 바탕이 되는 리눅스/윈도우 OS 이미지(디스크 템플릿)를 저장하고 관리합니다.
  - 테스트용으로는 약 20MB짜리 아주 가벼운 리눅스인 CirrOS나 qcow2 포맷 형태의 이미지를 자주 사용합니다.
  
#### 6. Cinder (Block Storage)
- AWS 대응 : EBS (Elastic Block Store)
- 무슨 일을 하나요?
  - VM에 추가로 장착할 수 있는 가상 블록 디스크(볼륨)를 관리합니다.
  - 핵심 특징 : VM을 삭제하더라도 Cinder로 만든 외장 하드는 삭제되지 않고 데이터가 남아있으며, 다른 VM에 다시 뗐다 붙일 수 있습니다.
  
####  7. Horizon (Dashboard)
- AWS 대응 : AWS Management Console
- 무슨 일을 하나요?
  - 터미널 타자 치기가 어려운 사용자를 위한 웹 UI(Dashboard)입니다. Python Django로 제작되었습니다.
  - 마우스 클릭으로 VM을 만들고 네트워크를 잇는 모든 작업은 내부적으로 앞에서 설명한 REST API 호출로 자동 변환됩니다.

</br>

#### 🌐 확장 : AWS 카탈로그와 1:1 대응하는 OpenStack 생태계
OpenStack에는 위 7개 외에도 30개가 넘는 부가 프로젝트가 있습니다. 신기하게도 퍼블릭 클라우드(AWS)의 서비스와 거의 1:1로 대응됩니다.

```
AWS (클라우드 서비스)   ↔   OpenStack (오픈소스 프로젝트)
--------------------------------------------------
S3 (오브젝트 스토리지)   ↔   Swift
ELB (로드밸런서)        ↔   Octavia
Route 53 (DNS)         ↔   Designate
EKS (쿠버네티스 서비스)  ↔   Magnum
RDS (데이터베이스)      ↔   Trove
KMS (암호화 키 관리)    ↔   Barbican
```

#### 💡 정리하며 : 왜 OpenStack을 배우면 다른 클라우드도 쉬워질까?
AWS, KakaoCloud, Naver Cloud 등 어떤 벤더사의 클라우드를 가더라도 "클라우드가 내부적으로 인프라를 가상화하고 제공하는 기본 규칙"은 전부 동일합니다.
OpenStack 구조를 통해 밑단 원리를 배운다면, 특정 클라우드 벤더에 종속되지 않는 인프라 엔지니어링 역량을 갖출 수 있게 됩니다!
